## BUG-1989 · KiriKiri 风险准入前仍提交并吞点击，宿主拒收后无弹窗
- **报告**：2026-09-02（用户：）
- **真实性**：✅ 真 bug。截图的 `needsRiskAcceptance / riskAcceptanceRequired` 说明 DLL、KiriKiri TJS 传感器和 runtime-layout provider 已经建立；该状态本身是逐 exe 左键风险尚未确认的预期 fail-closed，此时不弹卡是预期行为。截图中的青色选区也可能只是允许继续运行的 hover 几何高亮，单凭截图不能证明发生了 submit。真正错误是旧 KRKR 私有输入钩在该状态仍可直接执行 `fushiLookupProbe(true)`：它会写 `SubmitSeq`、画提交选区并向 KAG 返回 `true` 吞掉点击，而 Dart `GalIngameLookupController.handleHit` 会按设计拒收未准入 hit，于是形成“发生未授权提交、宿主拒收且游戏也没收到点击”。`lookup_enabled` 只表示几何发现继续存活，不能作为消费输入的许可。
- **[x] ① 已修复** — TJS 新增默认关闭的 `fushiLookupNativeInputReady`，submit Probe 先排空旧 visual transaction，再在任何新提交命中/提交高亮/`SubmitSeq` 之前 fail-open；hover Probe 继续运行，不破坏风险确认前的 provider 发现。KiriKiri pump 在 `OfferReady` 后只按 `GeometryProviderRegistry::OwnsReadyProvider(runtime_layout, KiriKiri)` 正向开闸，撤权检查位于 sensor wait/backoff/eval 的全部 early-return 之前；撤权同时推进 dismiss fence 并收起旧视觉。`PublishKirikiriLookupHit` 再查一次权威 ownership，拒绝撤权边沿排队的旧 submit 复活。（本提交）
- **[x] ② 已加自动化测试** — `kirikiri_lookup_source_guard_test.py` 新增独立且带变异自测的 v21 native-input 守卫，锁定默认关门、旧 visual 先退休、submit fail-open、撤权早于传感器退避、`OfferReady → OwnsReadyProvider → 正授权` 及发布二次门；`geometry_provider_registry_test.cpp` 锁定 KiriKiri Ready geometry 在风险未确认时不拥有输入、确认后只授权当前 owner、撤权/attachedOnly 立即关闭；`lookup_ipc_contract_test.cpp` 锁定 `nativeInputReady` true/false 独立代际；Dart controller 测试复现截图的 KiriKiri `riskAcceptanceRequired + kind=1/id=1 Ready`，确认前 `needsRiskAcceptance`、确认后 `activeNative`。
- **验证**：按用户要求跳过全量测试。聚焦测试通过：KRKR source guard 129 项；Dart attached controller 32 项；x86/x64 `fushi_geometry_provider_registry_test` 与 `fushi_lookup_ipc_contract_test`。x86/x64 Release hook、helper distribution 与 Windows Debug app 均增量构建成功，bundle 内两架构 DLL 哈希与刚编译产物一致。
- **实机回归**：本轮未代替用户操作 KRKR 真机。测试包位于 `fushi/build_codex/windows/x64/runner/Debug/fushi.exe`；风险确认前 hover 几何高亮仍可出现，但点击应继续交给游戏、`SubmitSeq` 不应推进且不弹卡；点击工作台“确认点击风险”后状态应进入 `activeNative`，下一次全新点击才提交并弹卡。
- **备注**：静态横向审计另发现 Siglus、Leaf/AQUAPLUS 的私有 click runtime 仍未接 v21 ownership，属于同类高风险缺口，应各自按单引擎任务修复；Ren'Py 是 Shift-only，不吞左键；SGRE 已修；其余生产路径为 attached-calibrated，不走引擎私有 native click。另有共享的 native-input 撤权 ack/route 关闭顺序竞态，但它不是截图稳态的直接根因，需单独设计 provider-specific disarm acknowledgement，不能在本修复里只交换两个 Dart await 冒充闭环。
