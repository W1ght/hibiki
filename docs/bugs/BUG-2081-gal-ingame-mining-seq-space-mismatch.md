## BUG-2081 · 内嵌查词制卡用几何命中序精配文本行序，跨 provider 必落空致静默失败
- **报告**：2026-09-03（适配 KiriKiri Z 新样本 `lapla.exe`（何度目かのはじめまして）时真机发现：游戏内单击查词弹卡正常，点卡上「+」制卡后 AnkiConnect `added:1`=0、屏幕无反馈）
- **真实性**：✅ 真 bug。根因 `fushi/lib/src/lookup/gal_hook_text_overlay_controller.dart:1864-1871`（原 `_resolveIngameMiningLineId` 的 `textGeneration != null` 分支）。内嵌查词命中的 `hit.textGeneration` 来自原生几何 provider 发布的 `lookup_geometry_text_generation`，其值是注入 TJS 传感器的**几何命中序** `hit_seq`（`native/galgame_hook/hook/adapters/kirikiri_adapter.inc:5461` `publication.text_generation = hit_seq`）；而文本行的 `sourceSequence` 是**文本行序**（Luna 发布序 `line.seq`，`fushi/lib/src/mining/gal_hook_session_controller.dart:2490`）。用户选 Luna 文本线程时，几何来自 TextRender 传感器、文本来自 LunaHook，两个计数空间互不相关，`entry.sourceSequence == textGeneration` 精配必然落空，随后 `return null`（fail closed）→ `_ingameMiningHandlerFor` 回 `{ankiConnect:false}`（`:1917`）→ popup 的 mine 分支只在 `ankiConnect` 为真时才动作 → 制卡静默失败。真机证据 `%TEMP%\hibiki_glookup.log`：`mine: mineEntry -> reply={ankiConnect: false, noteId: null}`，无 message（即 resolver 返回 null 那条，区别于 lease 抛异常）。此前 tenshi_sz 能出卡是文本恰走原生文本槽（与几何同 provider、seq 同源）；一旦文本来自 Luna 就暴露此结构缺陷，因此这不是单游戏问题、影响所有「Luna 文本 + 原生几何传感器」的 KiriKiri Z 内嵌查词制卡。
- **[x] ① 已修复** — `fushi/lib/src/lookup/gal_hook_text_overlay_controller.dart`：`_resolveIngameMiningLineId` 的 seq 精配失败后不再 fail closed，退回按**整行文本**定位当前 occurrence（新增 `_resolveIngameMiningLineIdByText`：最近优先取净句完整相等者，相等落空再走 >=8 净字的双向包含兜底）。session/HWND 门控不变；seq 精配仍先试（文本与几何同 provider 时零行为变化）。提交见分支 `claude/krkr-lapla-adapter`。真机复测 2026-09-03（lapla.exe）：单击「真理」查词 → 卡上「+」→ AnkiConnect 新增真卡，sentence 为点击整句、含完整句音频 + 视频片段。
- **[x] ② 已加自动化测试** — `fushi/test/lookup/gal_ingame_mining_line_resolution_test.dart`：① 几何命中序与文本行序不同空间（textGeneration 不等于任何 sourceSequence）时按整行文本命中最新 occurrence；② 净句完整相等优先于包含；③ session/HWND 不符仍返回 null；④ 短串（<8）不走包含兜底；⑤ seq 与 sourceSequence 同源时精配仍命中（不回归）。
- **备注**：与 BUG-1734（resolver 返回 null 的静默无反馈，已改为分因上报）叠加：本 bug 是让 resolver 不再无谓返回 null 的根因修复。相关 fold 修复见同分支 EmbedKrkrZ 末块折叠（`native/galgame_hook/include/luna_text_selector.h` `LunaLastPairedBlock`），两者都影响「点击整句 == 文本行」是否成立。
