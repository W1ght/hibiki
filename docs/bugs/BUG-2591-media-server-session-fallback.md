## BUG-2591 · Emby 服务端看不到 Fushi 在播：协商回落无会话即不发 Start
- **报告**：2026-09-19（用户：「希望能把 emby 和 fushi 的会话也一起修了，现在播了服务端好像不知道，bangumi 和豆瓣没法打格子」）
- **真实性**：⚠ 部分复现。用真 Emby 4.10.0.40（docker `emby/embyserver`）对 upstream/develop `332a075b994`（含 PR #1542）验真：
  1. **协议层通**：`fushi/test/sync/emby_live_session_probe_test.dart`（用真实 `JellyfinApi` / `JellyfinVideoClient`）→ PlaybackInfo 200 签发 PlaySessionId → `/Sessions/Playing` 204 → 服务器 `/Sessions` 出现 Client=Hibiki、NowPlayingItem=条目名 → 暂停 Progress 后 `IsPaused=true` → 97% 处 Stopped → `UserData.Played=true, PlayCount=1`、NowPlayingItem 清空。**用户描述的症状（服务端不知道在播）正是 #1542 之前的行为**（#1542 之前本仓从不发 Start），而 #1542 于 2026-09-18 才合入，晚于最新发布的 `v2.7.0-beta.14929`（09-15）与 `v2.7.0`（09-13）——用户手里的包大概率还没带。
  2. **真有一条会让服务端看不到的路径**：`fushi/lib/src/sync/jellyfin_video_client.dart` `_negotiatePlayback` 在 PlaybackInfo 协商失败（兼容层 404 / 回 HTML / 服务器 400 拒 DeviceProfile / 500 / 没给可播源）时回落为**无会话**，随后 `startRemoteVideoPlayback` 见 `session == null` 整个不发 Start；`putRemoteVideoPosition` 的 Progress 不带 PlaySessionId。真 Emby 实测：缺 PlaySessionId 的 Start / Progress 直接 400 `Value cannot be null. (Parameter 'key')`（只有 Stopped 无会话也收）——回落路径上服务器全程不知道在播、Progress 每 10s 吃一个 400，仪表盘不显示，Bangumi / 豆瓣等靠 Emby 播放事件打格子的插件跟着失灵。同时实测 **Emby 接受客户端自造的 PlaySessionId**（任意 32 位十六进制，Emby for Kodi 直播放就是这么签的），Start 204、NowPlayingItem 立刻出现。
- **[x] ① 已修复** — 回落会话 `JellyfinVideoClient._fallbackSession`：协商拿不到服务器签发的会话时客户端自造 `PlaySessionId`（`JellyfinPlaybackSession.newClientPlaySessionId`，`Random.secure` 16 字节十六进制）、按 `DirectPlay` 登记，Start / Progress / Stopped 全带它；`_sessionBody` 对空 `MediaSourceId` 不发空串；直出 URL 不变（飞牛只认带 MediaSourceId 的裸流地址，BUG-2254 ③）；回落会话非转码，Stopped 后不去 DELETE ActiveEncodings。
- **[x] ② 已加自动化测试** — `fushi/test/sync/jellyfin_playback_negotiation_test.dart`：回落（404 / HTML / 400）三态都得有 32 位十六进制会话、Start / Progress / Stopped 带同一 id、不删 ActiveEncodings；详情无媒体源时不发空 MediaSourceId；`newClientPlaySessionId` 形态与唯一性。真机：`fushi/test/sync/emby_live_session_probe_test.dart`（`FUSHI_EMBY_URL` 门控、默认 skip）对真 Emby 逐步核对 `/Sessions`；`integration_test/media_server_emby_live_itest.dart` 新增「播放 20s 后 `/Sessions` 里有 Client=Hibiki 且 NowPlayingItem 非空」断言（真 app 路径）。
- **备注**：
  - 用户的真 Emby 与 Bangumi / 豆瓣插件未复测。若升到含 #1542 的包后仍看不到会话，下一步取证：Emby 仪表盘 → 日志里搜 `Sessions/Playing` 的状态码；Fushi 侧错误日志搜 `JellyfinVideoClient.playbackInfo`（协商被拒会落在那）。
  - 打格子插件（kookxiang Bangumi / 豆瓣同步类）一般挂 Emby 的 `PlaybackStopped(PlayedToCompletion)` / `UserDataSaved(PlaybackFinished)`：Fushi 只在退出 / 换集 / 完成时发 Stopped（带当时位置），Emby 按位置 ≥ 90% 判看完——中途退出不算看完是服务器口径，不是本端 bug。
  - 本机 docker Emby 搭建：`emby/embyserver:latest` + Startup 向导 API（`/Startup/Configuration` → `/Startup/User` → `/Library/VirtualFolders?collectionType=tvshows` → `/Startup/Complete`），ffmpeg `testsrc2` 造 60s 集文件。
